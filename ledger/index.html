Ledger

A private personal finance tool. It turns “$142 at Walmart” into what was actually bought, by reading the receipt.

What this application is

Ledger is a personal finance application built and used by one person, Soroush Najafi, for his own household. It is not a commercial service and has no other users. It runs locally on his own computer rather than on a public server.

Its purpose is to categorize household spending accurately. Bank records show where money was spent but not what was bought, which makes budgeting inaccurate for shops that sell several categories of goods. Ledger reads the household's own paper and emailed receipts, extracts the individual items, and splits a single purchase across the right budget categories.

What data it accesses, and why

  • Transactions, through Plaid, for the owner's own bank and credit card accounts. Used to record spending, match receipts to the purchases they belong to, and report against a monthly budget.
  • Account names and the last four digits, so a receipt can be matched to the card it was paid with.

Access is read-only. The application cannot move money, make payments, or initiate transfers of any kind. It does not request or use identity, balance verification, routing numbers, investments, or income products.

How the data is protected

  • Data is stored in a local database file on the owner's own computer. It is not uploaded to any server and is not held by any third party.
  • The Plaid access token is encrypted at rest with AES-256-GCM. The encryption key is held outside the database, in an environment file, so a copy of the database alone cannot be used to reach any bank.
  • The application requires a username and password. Passwords are stored only as a salted scrypt hash and are verified in constant time.
  • Two-step verification is enabled: signing in also requires a time-based one-time code (TOTP, RFC 6238) from an authenticator app. The authenticator secret is itself encrypted at rest, and a session that has passed the password but not the code unlocks nothing.
  • Session tokens are stored as hashes, and session cookies are HTTP-only.
  • The web server listens on the local loopback address only, so it is not reachable from any network.
  • Repeated failed sign-in attempts are rate limited and then locked out, for both passwords and one-time codes.
  • Single-use recovery codes are stored hashed, never in readable form.

Data sharing and retention

No data is sold, licensed, shared, or otherwise disclosed to anyone. There are no advertisers, no analytics, and no third-party processors beyond Plaid, which supplies the transaction data itself.

A retention limit is enforced by the application itself, not just written down. Past the chosen period, receipt line items and stored receipt images are deleted automatically. The transactions and their category totals are kept, so historical budgets remain intact while the itemized personal detail does not accumulate indefinitely. The check runs daily and can also be applied on demand.

Everything can also be deleted at any time by the owner: individual transactions, receipts, accounts, or the bank connection itself. Disconnecting a bank revokes the access token at Plaid. It can equally be revoked from my.plaid.com or the bank's own website. No other person's data is ever held, so there are no third-party deletion requests to service.
